# 同花顺客户端中转服务

A 股券商（浙商证券、中信建投等）没有面向个人的登录接口。这个脚本跑在一台装了券商「同花顺版下单客户端」的 Windows 机器上，把客户端里的**资金和持仓**通过带口令的 HTTP 接口提供给局域网里的 Q-Limit。

- 默认只读（资金、持仓、当日委托、当日成交）；加 `--allow-trade` 启动后才开放限价买卖和撤单。
- 券商账号密码只留在客户端里，不经过钉钉，也不进 Q-Limit 的数据库。
- 靠 [easytrader](https://github.com/shidenggui/easytrader) 模拟操作客户端界面，客户端升级后可能失效。

## 准备

1. Windows 机器，安装 Python 3.8 – 3.11（easytrader 依赖的 pywinauto 0.6.6 较旧，不建议用更新的 Python）。
2. 安装券商提供的**同花顺版独立下单客户端**（安装目录里有 `xiadan.exe`），不是同花顺行情软件。
3. 打开客户端并**手动登录**，然后在客户端的「系统 → 系统设置」里：
   - 「界面设置」把界面不操作超时时间设为 0（否则会自动锁屏）；
   - 「交易设置」把默认买入/卖出价格、数量都设为空；
   - 「快速交易」关闭所有委托确认、成交回报之类的弹窗。
4. 客户端窗口不要最小化，脚本运行期间不要有人同时操作它。

## 运行

```bat
pip install -r requirements.txt

:: 第一步：先用示例数据确认网络打通（不碰客户端）
python ths_bridge.py --mock

:: 第二步：连接真实客户端
python ths_bridge.py --exe "C:\同花顺软件\同花顺\xiadan.exe"
```

启动后会打印访问口令（首次自动生成，保存在同目录 `bridge_token.txt`，之后重启不变）。首次运行时 Windows 防火墙会询问，选择允许专用网络。

本机自测：

```bat
curl http://127.0.0.1:8765/health
curl -H "X-Bridge-Token: 你的口令" http://127.0.0.1:8765/account
```

第二条应返回 `{"data": {"balance": {...}, "position": [...]}}`，执行时客户端会自动切到「查询 → 资金股票」页面。

## 读取持仓与验证码

持仓不是「另存为 xls」，而是把表格**复制到剪贴板**再解析。同花顺客户端对程序复制数据会弹一个
**「拷贝保护验证码」**对话框，本脚本已内置本地 OCR（[ddddocr](https://github.com/sml2h3/ddddocr)，
纯离线、无需 Tesseract）自动识别通过，单次读取约 4~6 秒属正常。

> 读取时客户端窗口必须**可见、不被遮挡**；OCR 连续失败会报错，重试即可。

## 开启交易

默认只能查询。要让 Q-Limit 网页能下单、撤单，启动时加 `--allow-trade`：

```bat
python ths_bridge.py --exe "C:\同花顺软件\同花顺\xiadan.exe" --allow-trade
```

用 `start_ths_bridge.bat` 启动的话，先设置环境变量再运行：

```bat
set THS_BRIDGE_ARGS=--allow-trade
start_ths_bridge.bat
```

- 只支持限价委托，代码必须是 6 位数字。
- 下单过程如果报错，委托**有可能已经报出去**，务必到客户端的「当日委托」里核对，不要直接重试。
- 所有下单、撤单请求都会打印在这个窗口里。
- 可以先用 `--mock --allow-trade` 走一遍流程，示例模式下单不会到达券商。

接口一览（除 `/health` 外都要带 `X-Bridge-Token`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 服务是否在跑、是否开启交易 |
| GET | `/account` | 资金与持仓 |
| GET | `/orders` | 当日委托 |
| GET | `/trades` | 当日成交 |
| POST | `/order` | 限价委托，`{"side":"buy","code":"600030","price":25.1,"amount":100}` |
| POST | `/cancel` | 撤单，`{"entrust_no":"..."}` |

## 接入 Q-Limit

**网页端（查询 + 交易）**：打开 Q-Limit「设置 → 服务端配置 → 同花顺交易」，填入中转服务地址和口令并保存（写入服务端 `.env`，重启不丢）。要下单还需在同一处开启「允许网页下单 / 撤单」并设置交易口令。然后点页面右上角的交易按钮。

**钉钉机器人**：私聊机器人发 `#CONFIG 同花顺`，按提示回复中转服务地址和口令，效果和在网页上配置一样（两边共用同一份配置）。之后可用 `#ACCOUNT`、`#ORDERS`、`#TRADES`；开启交易后可用 `#BUY 代码 数量 价格 交易口令`、`#SELL ...`、`#REVOKE 委托编号 交易口令`。

Q-Limit 跑在 Docker 里时，填 Windows 机器的局域网 IP，不要填 `127.0.0.1`。

## 排查

| 现象 | 处理 |
|---|---|
| `/health` 不通 | 检查防火墙、IP 和端口；Q-Limit 的机器要能访问 Windows 机器 |
| 返回「口令错误」 | 对照启动时打印的口令，或删除 `bridge_token.txt` 后重启重新生成 |
| 返回「读取同花顺客户端失败」 | 客户端是否已登录、是否锁屏、是否有弹窗挡着；`--exe` 路径是否就是正在运行的那个 `xiadan.exe`；窗口里看完整报错 |
| 资产能读、持仓读不到 | 持仓通过「复制到剪贴板」读取，客户端会弹「拷贝保护验证码」；本脚本用本地 OCR 自动识别（约 4~6 秒/次）。若持续失败，确认客户端窗口可见、未被遮挡、未锁屏 |
| 数字全是 `--` | 你的客户端字段名和预设不一样，把 `/account` 的返回贴出来即可适配 |

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--exe` | 无 | `xiadan.exe` 的完整路径 |
| `--host` | `0.0.0.0` | 监听地址 |
| `--port` | `8765` | 监听端口 |
| `--token` | 自动生成 | 访问口令 |
| `--allow-trade` | 关 | 开放下单和撤单接口 |
| `--mock` | 关 | 返回示例数据，不连接客户端 |
